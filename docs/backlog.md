- B6 What an item set must satisfy and what the learner sees when it does not: every item has exactly one answer in every dimension, drawn from that dimension's categories, and a set that breaks this shows a clear error in place of the board.
  - Reason: the requirements assume one category per item per dimension and ask whether more than one is allowed; the error is what the learner sees instead of a broken quiz.
  - Owner: /product-decide
- B14 Can the correct category of an item in a dimension be set inside the app, and by whom: the learner themselves or a separate author?
  - Reason: the answers live in the hand-edited data file, and the MVP has no in-app editor; an editor adds a second mode to the one screen, a way to save what was made, and a way to pick which set to play.
  - Owner: /product-decide
- B15 Can a dimension, with its name and categories, be created inside the app, and by whom: the learner themselves or a separate author?
  - Reason: dimensions live in the hand-edited data file, and the MVP has no in-app editor; a new dimension needs an answer for every item, which the rule for a usable set demands.
  - Owner: /product-decide
- B17 What does assistive technology speak for the ⓘ on a card, a dimension, a zone and a deck?
  - Reason: every ⓘ shows "ⓘ" alone, so assistive technology speaks the same for each, and a learner who uses it cannot tell which card, dimension, zone or deck an ⓘ opens.
  - Owner: /product-decide
- B18 What does the learner meet when the deck they are on is deleted from another device, and what becomes of their changes to it still waiting to be kept?
  - Reason: one deck is changed from any device, and a deck can be deleted. A waiting change that no longer fits the deck as kept is not kept and is named in a line, but a learner on the board of a deck deleted meanwhile has no screen decided for them.
  - Owner: /product-decide
